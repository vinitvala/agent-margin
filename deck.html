Agent Margin01 / 10

Per-ticket AI cost attribution for software agencies

Clients want a discount because you use AI. Nobody can tell you what AI actually cost.

Agent Margin reads Claude Code session transcripts, attributes every dollar of agent capacity to a specific Linear ticket, and answers one question: did the discount you gave break even?

Working software · run against its own build history · github.com/vinitvala/agent-margin

The problem02 / 10

Fixed revenue. Variable, invisible cost.

An agency bills a fixed fee, then burns an unknown amount on coding agents underneath. Clients now open with "you use AI, so we want 20–30% off" — and agencies concede, because they have no number to argue with.

The discount is negotiated in the first meeting. The cost shows up over eleven weeks, spread across forty tickets, and nobody ever reconciles the two.

The question isn't "what did we spend on AI." It's "was the discount we already gave smaller or larger than what AI actually returned." No PSA tool answers that.

Why it's unanswered03 / 10

The cost isn't just unmeasured. It's structurally invisible.

  • Seat billing hides it. On a Max subscription the console shows zero per-token spend. The seat is a flat fee, so there is no invoice to attribute.
  • Sessions don't map to tickets. One agent session routinely spans several branches. Attribute at the session level and cost smears evenly across tickets — which produces a clean-looking, completely wrong ledger.
  • The data is local and undocumented. It sits in JSONL transcripts on each developer's machine, with cache-token accounting that most parsers get wrong.

So the honest state of the industry: the discount is a negotiating concession, not a calculation.

The mechanism04 / 10

Every transcript record carries the git branch that produced it.

That's the join. Branch names carry the ticket ID, so cost attributes at the record level, not the session level — the one decision that makes the number defensible.

StageWhat it does
walkRead every JSONL transcript, including subagent sessions
dedupCollapse multi-block turns on message.id
priceCache-aware: 1h writes 2.0×, 5m 1.25×, reads 0.10×
attributeBranch → ticket ID → Linear issue
allocateToken share → share of the real seat cost

One command. Python, stdlib plus two packages. No database, no server.

The insight05 / 10

Token cost isn't a price. It's an allocation key.

Under a subscription, no money is billed per token — so reporting "$5,533 of agent spend" would simply be false. The seat is the real cost. Token usage is the driver that allocates it.

allocated(ticket) = (ticket_tokens ÷ all_tokens) × seat_cost × seats

Now every number is true. You aren't claiming a ticket spent $39 — you're saying it consumed 19.5% of that developer's agent capacity, so 19.5% of their seat lands on it. That's ordinary cost accounting, it survives a CFO, and it works identically under subscription and metered billing.

It also reframes the pitch: under a subscription the scarce resource is capacity, not cash. "Which client consumed 60% of our agent capacity this month?" is a question no PSA tool can answer and every principal recognises.

The finding07 / 10

Of all agent spend on this project

66%

wasn't on any ticket · $40.38

It ran on branches with no ticket ID — merges, spikes, unbranched fixes. Real work, real cost, not traceable to anything you could bill or defend.

We report it rather than absorbing it into the ticket rows. A ledger that reconciles to 100% attributed is usually hiding this, not free of it — and every agency principal who sees the number recognises their own situation immediately.

This is the finding that sells the product, and it only exists because we refused to smear unattributable cost across tickets to make the output look tidy.

Honesty by construction08 / 10

Measured, modelled, and assumed are separated in the schema.

The failure mode for a tool like this isn't crashing. It's producing a confident, well-formatted number that's fiction. So the ledger makes that structurally hard.

ZoneContentsRule
measuredTokens, capacity share, allocated cost, attributionObserved only
modelledHours saved, break-even, gap valueNull without a human baseline
inputsContract value, discount, blended rateFlagged unverified
  • An earlier build multiplied story points by a constant to produce a $13,560 headline. That path was deleted — it now raises rather than falling back.
  • Promotional model pricing carries an expiry and refuses to price once stale.
  • An unpriced model aborts the build with a list of what to add, never a guessed rate.
Verification09 / 10

Checked against two independently written parsers.

The subscription means there's no invoice to reconcile against, so we triangulated on token totals instead — comparing counts, not dollars, since price tables differ.

0.00%Delta vs token-dashboard
<0.75%Delta vs claude-usage

Exact agreement on input, output, cache reads, both cache-write tiers, and row count. Two implementations agreeing to the token would take an identical mistake in both.

It found two real bugs in ours:

  • A non-recursive file glob was skipping every subagent transcript — all sidechain cost was silently absent.
  • Dedup kept the first record per turn, not the consolidated one. Partial records carry a placeholder output count, so output was undercounted by 3.6%.
